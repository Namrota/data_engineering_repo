Part 2 — Pipeline Lifecycle: Ingestion, Storage, Processing, and Serving
A data pipeline normally moves through a sequence such as source → ingestion → storage → processing → useful output. 
Monitoring checks whether those steps are working as expected.

Part 3 — Transformation, Batch Processing, and Streaming Processing
Transformation changes raw data into a more useful form. Batch processing handles a collected set of records together. 
Streaming processing handles continuously arriving events with low delay.

Q. 18 — Compare Two Pipeline Designs

Design A
Source -> Clean -> Final report

Design B
Source -> Store received data -> Clean -> Final report

Solution: Design B will provide a more cleaner approach because it stores the extracted data and then goes to the cleaning step. If in future the business rules change, it can be re-run from the point whne the data was stored.
